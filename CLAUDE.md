# Auto Battler: Project Notes

A 3D TFT-style auto battler built in **Godot 4.7** with GDScript. Working title **Hare & Hex** (renamed from AZTactics on 2026-10-22; shown on the splash screen and main menu and set as the window title at runtime; the project's `config/name` is "Hare&Hex" since commit 4ae86e6 (2026-10-24; it was "Azerothtactics"), and Godot derives the save folder from it, so saves now live in `app_userdata/Hare&Hex`). Single player: free play and a campaign; a PvP mode is planned.

> These notes describe the intended design as built step by step. If the code and these notes disagree, the code wins. Update this file when systems change.

## Scene tree (main.tscn)

```
Main (Node3D)
 ├─ WorldEnvironment             environment = tres/world_env.tres (Linear tonemap, exposure 0.92, saturation 0.92, HDR glow, depth haze; lit per biome by BoardThemes.apply_look)
 ├─ DirectionalLight3D
 ├─ Board (Node3D)                board.gd, in group "board"
 │   ├─ Bench (Node3D)            plain Node3D, your bench + sell hex and the enemy's bench, spawned at runtime
 │   ├─ Units (Node3D)            plain Node3D, ALL unit instances live here
 │   ├─ Tiles (Node3D)            plain Node3D, tiles spawned at runtime
 │   └─ Kings (Node3D)            created in code by board.gd: the two king hexes (king.gd), one per side; not in the .tscn
 ├─ UI                            instance of ui.tscn (see below)
 ├─ "Game Manager" (Node)         game_manager.gd  -- note the SPACE in the node name
 ├─ DragController (Node)         drag_controller.gd
 └─ CameraRig (Node3D)            camera_rig.gd (sets its own position, tilt and the camera's distance and FOV at runtime)
     └─ Camera3D
```

The Game Manager exports set in main.tscn: `prep_time = 30` (seconds; campaign levels with `prep_time = 0` use it, the tutorial overrides it), `unit_pool` = all 65 unit .tres files (this is the **roster**, not the shared pool), `item_roster` = the 15 item .tres files, `enemy_base_scale = 0.4`, `enemy_scale_per_round = 0.05` (free-play random enemies). `only_units_with_models` (default **off** since all 65 units have models): when on, `_begin_run` drops every unit without a model from `unit_pool`. Keep it off; it only matters again if a unit is added without a model. `debug_level` (CampaignLevel) is empty: it only matters when main.tscn is run directly (F6 in the editor) to jump straight into a campaign level for testing; runs started from the main menu ignore it (`GameState.launched_from_menu`). Always load a level **file** into it; a "New CampaignLevel" has no waves, so the game warns and plays free play instead. `continue_saved_run` (default on): with Debug Level set, running main.tscn directly continues the saved chapter run if it's in the same chapter.

**splash.tscn** (the project's main scene, `run/main_scene`; `splash.gd`, class Splash): the launch screen. Godot's boot splash (`application/boot_splash/*`: `icon.png`, the hare logo, at its own size, unfiltered, on `#0b0c12`, which is also the default clear colour) shows while the engine starts; the splash takes over with the logo in the same place and size, lifts it into place, the gold "Hare & Hex" title and "A HEX AUTO BATTLER" rise in under it with a chime, a 2-star Assassin (no tile) waves beside the logo (`UnitModel.wave()`), and after `HOLD` (2.6 s) everything fades back to the menu's radial background and the menu fades its buttons in (`Splash.fade_menu_in`). The menu scene loads on a worker thread meanwhile, then `Preload.warm_run` starts; menu music starts here and carries on; the BUG button is hidden while it shows. Any key, click, touch or pad button skips. Headless it goes straight to the menu.

**menu.tscn**: a full-screen Control with `main_menu.gd`, which builds everything in code: styled in the HUD / side-box look (behind it a moving voxel world, `MenuBackdrop`, under a dark vignette down the middle; the dark radial background is its curtain, the title in the gold pixel font with a hard shadow, DockKit slate buttons with Continue in gold and the PvP buttons edged blue, screens as HudPlates with gold top edges and pixel-font headings, campaign levels as rows with coloured status, the confirm dialog with its own small theme); title "Hare & Hex", Continue (only with a saved chapter run), then **SINGLE PLAYER**: Tutorial ("(start here)" for new players, "(done)" once completed), Campaign panel (chapters, levels with status: Completed/best HP, Not completed, Locked; Start chapter), Free Play; then **PVP** (tinted blue): **Async PvP** (a real mode: free-play rules against ghost boards, see Async PvP below; sets `GameState.ghost_mode`) and Lobby (2-8 players; see Live lobbies below); then King / Planner / Settings / Credits / Quit on one row (Planner: the team planner with the full roster, to plan and save comps before a run) (Credits: "Music By Joe Gallagher" with a link to the composer's SoundCloud, and the fonts; Keybinds is not on the front menu, it opens from Settings). The menu must fit a 648 px tall window (`menu_checks` measures it). Starting a run sets `GameState.run_level` / `run_campaign` / `run_carry` / `launched_from_menu`, calls `reset()` and changes to main.tscn.

The letter label is created in code. A unit whose UnitData has a `model` hides the capsule and letter label, puts its UnitModel in ModelHolder and gets a team ring at its feet instead.
`Tiles.tscn`: StaticBody3D root with `tile.gd` (collision layer 1), 6-sided CylinderMesh (radius 0.95, no rotation applied in the scene). Hex layout math in board.gd is **pointy-top**.

## Autoloads

- **GamepadControls** (`gamepad_controls.gd`): controller support on PC; see "Controller" under UI behaviour. Takes the pad events off Godot's default ui_* actions in `_ready` (so A / B / D-pad don't move GUI focus or fire ui_cancel) and sends mouse events and shortcut keys instead.
- **TouchControls** (`touch_controls.gd`): touch screen support; see "Touch controls" under UI behaviour. Reads only InputEventScreenTouch / ScreenDrag, so mouse and keyboard play is unaffected.
- **ScreenFilter** (`screen_filter.gd`): the colour-blind filter (see Settings).
- **Sound effects** (`sfx.gd`, autoload `Sfx`): `Sfx.play(&"hit")` plays `audio/sfx/<name>.wav` on the "SFX" bus (`Settings.sfx_bus()`, `Settings.sfx_volume`, Settings > Audio > Sound effects). A pool of 12 players, a per-sound cooldown (thins out fight spam), per-sound gain trims and a little seeded pitch variety (own RNG, never the game's). `Sfx.muted > 0` silences it: `resolve_combat` mutes while it runs a whole fight. Hooked in: shop (buy / sell / reroll / Buy XP / lock / error), drag (pickup / place), items (pickup when an item drag starts; `equip` clink, `resonance` chime when the item wakes a new resonance, `tongs` for Tinker’s Tongs, `error` when it won’t fit; `DragController.item_landed`, also in lobbies), merge, level-up, fight start horn, run won / lost, and in `unit.gd` swing / hit / crit / death / cast. Easter egg: a won fight (single player and lobbies, via `Events.combat_ended`) plays `easter_egg.wav` (a recorded clip, not from synth_sfx.py; about 2.8 s) once in 100000 (`Sfx.EASTER_ODDS`, its own unseeded RNG). Add a sound by adding it to `tools/synth_sfx.py`, running it (`python3 tools/synth_sfx.py audio/sfx`), then `--import`. `played` counts plays for tests.
- **BugReporter** (`scenes/BugReportUI.tscn` + `Scripts/BugReportUI.gd`, CanvasLayer 100, works while paused): a small BUG button bottom left (above the shop bar, on the menu and in runs) folds out a report panel in the HUD look: title, name (remembered in `user://bug_report.cfg`), severity (Critical / High / Medium / Low / Cosmetic / Suggestion), what happened, "attach game info" (build, window, mode, round, phase, seed, level / gold / HP, board and theme) and "attach a screenshot" (taken when the panel opens, 960 px wide). Send posts a Discord embed to the webhook (multipart with the PNG), with a 10 s cooldown, no mentions, the description cut to fit. **The webhook URL is a secret and never goes in code or git:** it is read from `res://bug_report_webhook.txt` (git-ignored, like `docs/bug_report_webhook.md`); an export needs `bug_report_webhook.txt` in its export filter, and without the file Send says reports aren't set up. While it is open, `BugReporter.typing()` stops F from selling (DragController) and `is_open` makes Esc close it before the pause menu (RightDock).
- **Music** (`music.gd`): the soundtrack on the "Music" bus (`Settings.music_bus()`, sent to Master; keeps playing while paused). `Music.play("menu" / "game" / "boss")` crossfades (1.2 s; the same track keeps playing). The main menu plays "menu"; GameManager picks "boss" or "game" at every PREP start (`is_boss_round()`: a chapter level's last wave or free play's / async PvP's round 39; the tutorial has none).
- **Telemetry** (`telemetry.gd`): anonymous tester stats (`docs/telemetry.md`): a random install id, sessions, `run_start` / `fight` / `run_end` (mode, level, round, result, length, comp, FPS), tutorial steps, menu screens, and an `unclean_exit` on the launch after a crash. Queued in `user://telemetry_queue.json` (max 3000) and posted in batches to `OnlineConfig.telemetry_url()` (the ghost service unless overridden), so nothing leaves the PC until a service is hosted. On by default with a first-launch notice (main menu), switch in Settings > Privacy; off in the editor (`-- --telemetry` turns it on) and headless. Hooks: `GameManager._ready` (`run_started`), `tutorial._enter_step`, `main_menu._show_panel`, `lobby_game._show_end` / `_on_lost`; the rest follows `Events`. A new mode needs a name in `Telemetry.mode_of` and `TelemetryStats.MODES`; a new event name in `TelemetryStats.EVENTS` (the service drops unknown names).
- **Events** (`events.gd`): all global signals, plus `enum Phase { PREP, COMBAT, RESULT }`.
- **GameState** (`GameState.gd`): **run-wide** state only: `round_number`, stage math, shop odds table, `base_income_for_round`, `ITEM_DROP_ROUNDS` / `item_drop_rounds()`, `damage_for_loss`, `reset()` (round + every player), and the run setup: `run_level` (CampaignLevel or null = free play), `run_campaign`, `run_carry` (chapter run state for the next level), `run_carried`, `run_seed` / `next_seed` (set `next_seed` before a run to replay it exactly), `begin_run(level, campaign) -> carry`, `launched_from_menu`, `MENU_SCENE`, `go_to_menu()`. `run_level` / `run_campaign` / `run_carry` survive `reset()`.
  - **Per-player state is in `PlayerState`** (`player_state.gd`): `GameState.me` is the local player, `GameState.players` everyone in the run (just `[me]` for now). Fields: `gold`, `level`, `xp`, `player_hp`, `start_hp` (HP-pack cap), `win_streak` / `loss_streak`, `items`, `cheap_shop`, `shop_offers`, `shop_locked`, `shop_has_rolled`, `last_combat_won`, `rng` (this player's shop and drops, seeded from the run seed and `id`). Methods: `xp_needed`, `add_xp`, `max_board_units`, `interest_gold`, `total_income_for_round`, `record_result`, `streak_bonus`, `heal`, `reset`. Only a player with `is_local` emits the HUD signals (gold_changed, hp_changed, xp_changed, streak_changed, items_changed). **Always write `GameState.me.gold` etc.; `GameState.gold` no longer exists.**

Signals in Events: `phase_changed`, `gold_changed`, `shop_rolled`, `unit_bought`, `combat_ended`, `xp_changed`, `reroll_pressed`, `buy_xp_pressed`, `board_limit_hit`, `round_changed`, `streak_changed`, `hp_changed`, `unit_sold(data, star, refund)`, `run_won`, `run_lost`, `items_changed`, `item_drag_started(index)`, `item_drag_ended`, `shop_lock_changed(locked)`, `team_plan_changed`, `opponent_announced(text)`.

## Core scripts

| Script | Responsibility |
|---|---|
| `board.gd` (class Board) | Hex grid (7 cols x 8 rows; rows 0-3 enemy, 4-7 player), bench (9 slots), sell zone, the two kings (`kings`, `king_of`, `king_spot`, placed after every `refresh_unlocks`), tile unlocking by level, seam border, hex math + BFS pathfinding, merging, selling; `apply_theme(id, seed)` gives the board the biome's plain voxel tiles (the only ones played on), the bench, sell hex and kings theirs, fills everything the camera can show with scenery from the seed (`_build_backdrop`, `backdrop_cells`: noise groves, meadows and rocky patches, gentle hills past the two level hexes round the board, the scenery a voxel lower and a shade darker so the board reads as a bright plateau, locked board hexes as darker sunken ground, nothing tall beside or in front of the board, never under the bench; one MultiMesh per tile kind; own RNG; desert mirages) and sets the backdrop colour |
| `board_themes.gd` (class BoardThemes) | The 12 biomes (`ORDER`, `WHERE`: which level uses it), `for_run(level, seed)` (the level's `theme`, else one from the run seed), `tile(id, part)` (a baked mesh), `backdrop()`, the lighting (`LIGHT`: per biome sun colour / strength / pitch / yaw, ambient colour and strength, haze colour and amount, glow strength; `apply_look(id, env, sun)`, called by `Board.apply_theme` on main.tscn's WorldEnvironment (`tres/world_env.tres`) and DirectionalLight3D) |
| `voxel_tiles.gd` (class VoxelTiles) | The voxel hex tiles (docs/hex-tile-design-plan.md): 16 voxels across, 4 deep, the top colour dripping over the sides; every tile is cut to a true hexagon (`HEX_A` = sqrt(3)/2 less `SEAM` 0.025, a thin even gap, so neighbours fit edge to edge at any sixth of a turn): voxel faces crossing a side are clipped (`_clip`), voxels outside are dropped and the six sides are smooth walls coloured voxel by voxel (`_walls`); `hex_columns()` is every column the hexagon touches and `_depth()` how far in a column is (the drip and the bench frame use it); `BIOMES` (palettes and what each decor slot and the two trees are in each biome), the voxel grid and mesher (`Grid`, `build`: vertex colours on `tres/voxel_solid.tres` and `voxel_glow.tres`), the prop recipes (`Props`), baked ambient occlusion (`_corner_ao`, `AO_LEVELS`: corners in creases and under overhangs are darkened in the vertex colours; glowing voxels skip it), `make()` for the bake tool and `mesh()` to load a baked tile |
| `interest_stack.gd` (class InterestStack) | Your interest as a pile of gold: its own hex just right of your half of the board (`Board.INTEREST_CELL` = (7, 6), `Board.interest`; skinned like a board tile, gold outline, no scenery there) with one coin per 10 gold banked up to the interest cap (`PlayerState.interest_gold`, so the Merchant King shows 7). ## Game rules implemented

**Phases:** PREP (timer, `prep_time` export; untimed with a START FIGHT button in async PvP and campaign chapter levels, `GameManager.manual_start`) -> COMBAT -> RESULT -> PREP. `_enter()` drives it and is guarded by `game_over`. RESULT waits `GameManager.result_pause` (3 s; 0 in headless runs, so the check suites and the bot don't wait) on a child Timer before the next PREP (`_next_round`), so the fallers and the victory dance finish first; lobbies wait `LobbyServer.result_time` after the last fight ends. `_end_combat()` must start with `if not fighting: return` (missing it caused rounds to be skipped).

**Stages:** 7 stages. Stage 1 = 3 rounds, stages 2-7 = 6 rounds (39 total). `round_number` is the overall round; `stage()` / `round_in_stage()` derive the display (e.g. Stage 2-4).

**Economy:**
- Start with 2 gold.
- Passive income: 1-1: 0, 1-2: 2, 1-3: 3, 2-1: 4, then 5 per round.
- Interest: +1 per 10 gold banked, max +5.
- Streaks: win or loss streak of 2-3 = +1, 4 = +2, 5+ = +3.
- Round 1-1 shop (`cheap_shop`) is limited to 1-cost units at normal price.
- Win a fight: +1 gold.
- Reroll 2g, any time (also mid-fight; not while the shop is locked). Buy XP 4g for 4 XP (any time, including combat; not at level 10, where the button greys out: `PlayerState.is_max_level`).
- Selling refunds `cost * 3^(star-1)`, applied immediately (bench units can be sold during combat).
- Gold label tooltip shows next round's base / interest / streak / total.

**Levels and board:**
- +2 XP per round. XP table in GameState.
- Unit cap on board = level. Max level 10 (`XP_TABLE` 9: 100).
- **Auto-fill:** when a fight starts, free board slots (under the cap, on unlocked tiles) are filled from the bench, leftmost bench unit first (`Board.auto_fill`, called in `start_combat` before the position snapshot, so those units stay on the board afterwards). Each takes a spot that suits it (`Board.open_tile_for`): melee (range 1) the frontmost open row, range 2 the second row, ranged (3+) the backmost; within a row the tile nearest the centre column.
- **Benches:** your 9 bench slots and the sell hex form one row one hex row past the board, on the same hex grid as the board and the scenery (row 8, so every hex slots in), as near the middle under the board as the grid allows: a quarter hex right of it (`bench_to_world`). The enemy has a matching 9-slot bench the same one row beyond the far edge of the board (row -1, `enemy_bench_to_world`); it is scenery for now, as no enemy keeps units on a bench. Both use the biome's bench tile: its own ground inside a raised frame in the biome's bench colour (`VoxelTiles._bench`).
- Board starts with 2 tiles per side (front row center) and grows evenly to the full board at level 8 (`tiles_open_for_level`). New tiles from a mid-combat level-up appear at the next PREP.
- **Interest pile:** a hex right of your half (row 6) stacks one gold coin per 10 gold banked, up to the interest cap (`interest_stack.gd`).
- Gold seam border drawn only between unlocked player front-row tiles and unlocked enemy tiles.
- **Kings:** every 10 s of a fight each side's king strikes one random enemy unit anywhere on the board (not hidden ones) for 30 + 10 per level of its player; kings can't be hurt or targeted. Each skin has its own animated attack (`King.strike`). Your king's skin (picked on the main menu, `KingSkins`) brings its power: the Golden Lion's on the same beat in every fight; the other 8 are run powers (`KingPowers`, free play and async PvP only). The enemy king in single player (campaign, free play, ghosts) has no skin effect; a ghost wears the skin its player had (snapshots carry `king`, a look only), and a Shadow King takes the enemy king's shape. Single player: `GameManager.start_combat` sets `runner.king_skins` / `king_levels` / `king_seed` (run seed + round). Lobbies: the server puts `home_king`, `away_king` and `away_level` in each fight description and `Arena.set_kings` reads them, so every copy of a fight matches (protocol version 2: hello carries your king). **Placement:** each side has one king on an extra hex at the left edge of its open tiles: the player's in row 5, the enemy's in row 2 (`Board.KING_ROWS`, index = team). `Board.king_spot(team)` puts it one hex left of the leftmost open tile of that row, so it sits against the board and slides outwards (0.4 s) every time `refresh_unlocks` opens tiles. While that row has no open tile yet (level 1 only opens the start row) it hangs half a hex further left off the nearest open row, still touching the edge and never on an open tile. It is a `King` node, not a `Unit`, so combat, targeting, the unit cap, merging, selling and dragging don't see it. The hex is skinned with the theme like a board tile (`apply_theme`). On a 4:3 window the left box covers both king hexes (it already clips the board's left edge there, and the SELL hex is cut off on the right); collapse the box to see them. The camera was left alone on purpose: centring the board with the kings would push the SELL hex further off the right edge.

**Shop odds (% for 1/2/3/4/5 cost) by level:** 1-2: 100/0/0/0/0, 3: 75/25, 4: 55/30/15, 5: 45/33/20/2, 6: 30/40/25/5, 7: 19/30/35/15/1, 8: 15/20/35/25/5, 9: 10/15/30/30/15, 10: 5/10/20/35/30 (level 10 added with synergies v2 so a 9-piece trait leaves a flex slot). If no unit exists at a rolled cost, falls back to the nearest cost.

**Shared unit pool:** Copies per unit by cost: 1: 30, 2: 25, 3: 18, 4: 10, 5: 9 (`UnitPool.COPIES_PER_COST`). Shop offers are taken from the pool when rolled; unbought offers go back on the next roll. Bought units stay out. Selling returns `3^(star-1)` copies. Picks within a cost are weighted by copies left; an empty cost falls back to the nearest cost with copies; if the pool runs dry the slot is left empty. Enemies do not draw from the pool. `GameManager.shared_pool` owns it (rebuilt on scene reload).

**Units and merging:** 3 copies (same `display_name`, same star) merge into the next star, max 3. Star multipliers: HP/dmg x1.0 / x1.8 / x3.2, model scale 1.0 / 1.2 / 1.45. A 3-star 5-cost gets x5 instead of x3.2 (`Unit.star_mult`, `FIVE_COST_3STAR`; plain-number ability values scale the same way). **4 stars (ascension, 2026-10-26, the user's design):** only by the Ancient Sigil (Items), never by merging: a 3-star unit holding it that survives 8 won fights becomes 4-star (`Unit.count_sigil_win`, `ascend`; `MAX_STAR` 4): x5 HP and damage (5-costs x7.5, `FIVE_COST_4STAR`), scale 1.6, the astral model (`<unit>_4star.glb`: star-flecked, a halo, motes on an `aura` bone), a violet star mark, ability arrays at their 3-star value; the sigil is used up. A 4-star sells and returns copies as its 3-star (`UnitPool.copies_in` caps at 3: 9 copies, 9x cost). Ascension shows `Vfx.ascend` and plays `ascend`, and sends `Events.unit_ascended`; lobbies count the marks on the server (`LobbyServer._apply_result`). Saves, waves, ghosts and fight descriptions accept stars 1-4. Merges run after buys, after drops (prep only), and at PREP start. Buying on a full bench is allowed if it completes a merge. Units bought during combat go to the bench and merge only with copies on the bench (`merge_all(bench_only)`, `would_complete_merge(d, bench_only)`): units fighting on the board are left alone until the next PREP start.

**Combat (deterministic):** the same two boards always produce the same fight, at any frame rate. `GameManager.combat_tick()` runs once per physics frame with a fixed `COMBAT_TICK` (1/60 s); units act in a fixed order (`_combat_order`: each side by tile row then column, interleaved player/enemy, never node order); target ties go to the lower tile (`Board.tile_order`); movement is stepped per tick (`Unit.move_from` / `move_to` / `move_progress`), not tweened. `resolve_combat()` runs a fight to the end instantly. The run RNG is seeded (`GameManager.rng` for random enemies and placement, `PlayerState.rng` for shops and drops); never use `randf()` / `randi()` / `pick_random()` / `shuffle()` in game logic. Tile-to-tile movement on the hex grid (BFS, occupied tiles are walls, units claim their next tile before moving). `attack_range` is in tiles, `move_speed` is tiles/sec. Units target the nearest enemy; a unit that dashes or leaps away (`leap_to`) drops every attacker targeting it, so they pick again. Dead units are hidden, not freed, and restored after combat. Player board positions are snapshotted at combat start and restored after. 60 s timeout counts as a loss.

**Unit models:** all 65 units have voxel models (`UnitData.model` -> `scenes/models/<unit>.tscn` -> `models/units/<file base>_{1,2,3}star.glb`; the 55 newer units map display name to animal file base in `menagerie/README.md`, e.g. Militia -> `militia_badger`). The capsule placeholder is only a fallback for a unit without a model. Enemies with a model get an ember ring at their feet (`#ff8a4c`), yours a blue one (`#6cc4ff`); only capsules are painted red. `Unit.mine()`: your own units (a uid and no `source_uid`) are always yours, so a lobby's away view doesn't paint your bench as the enemy's; moves face their tile in world space (`_world`), so units don't walk backwards on a turned board. Out of a fight your units (bench, and the board during PREP) face the camera (`Unit.face_rest`; world +Z, also with the lobby view turned) and enemies face you; `begin_combat` turns board units to face the other side (`face_board`), `look_at` turns them in the fight and `end_combat` turns your units back to the camera. Animations: walk while `moving`, attack on each swing (sped up when `attack_interval()` is shorter than the clip), skill on a cast, hit when damaged (at most every 0.6 s, never cutting off a swing, cast or death), death when killed, victory for 2.6 s for your survivors after a won fight. A unit with a model that dies stays visible (no bars) while it falls and hides about 1.6 s later; the death is visual only, `dead` and the tile are cleared at once. Enemies are freed when the fight ends (`Unit.leave_fight`): one that is still falling, or still standing after beating you, leaves a `StandIn` (its ModelHolder under Main) that finishes the clip and frees itself. Bars sit above the model's head with room for the item row under them (`Unit.bar_height` = the model's height at its star + `BAR_GAP` + `ITEM_ROOM`; `head_height()` is the old line, used for aiming item drops). The imported glb materials have vertex colour as albedo switched on at runtime (the importer leaves it off). Glow parts (`glow_<hex>` surfaces) get `UnitModel.GLOW_ENERGY` emission, so they bloom when Glow & fog is on. The 4-star "astral" models are not used (still in `menagerie/models/glb/`). **Held items:** each hand's item is skinned to `weapon_r` / `weapon_l`, children of the arms with their pivot at the hand. Left-hand bows, crossbows, muskets and shields used to be drawn at a fixed column near the voxel grid's edge, 2 voxels (Treant 1) beside the hand, so they floated next to the unit in every clip and star; on 2026-10-26 their voxels were moved against the hand in the glbs themselves (16 units: Archer, Scout, Frost Archer, Nightstalker, Frostling, Dwarf Gunner, Knight, Guardian, Militia, Skeleton, Ironbeard, Paladin, Magma Guard, Titan, Frost Giant, Treant; also the menagerie copies), and the generator does the same (`Model.close_grip` in `menagerie/source/vox.py`, called by `finish`; not run yet, Python isn't on this PC). Check with `tools/weapon_shots`.

**Mana and abilities:** +10 per attack, +10% of damage taken (max 15 per hit); none while stunned or silenced, and casts give none. Resets to `start_mana` each fight. At full mana (and its target in range) the unit casts its ability instead of attacking: `Abilities.cast` runs it and its own animated effect shows it (no name popup since 2026-10-25), the caster is locked 0.5 s (longer for channels) and mana resets to 0. All 65 units have their own ability (`docs/abilities.md`). Ability mechanics in `unit.gd`: stun, silence, blind, taunt, leaps (`leap_to`: the tile is claimed at once, the model flies there), untargetable (skipped by `Board.nearest_enemy` and `Abilities.targets`; areas still hit), empowered attacks, thorns, `on_death`, summons (`summoned`: temporary units that join `GameManager.combatants` via `add_summon` and are freed when the fight ends; no traits, items or selling), zones (`GameManager.add_zone`: miasma, grove, winter; ticked before the units), link, parry, doom, root, charm (`foe_team()`; a pink-violet hex sigil, ring and thread mark it), raising the dead, eruptions; dying goes through `_fall()`, timed buffs (`add_buff`: as, dmg, dr, vamp, regen; recasting refreshes), ability shields that run out (`add_timed_shield`), `heal`, queued hits (`queue_action`); ability damage uses `damage_bonus()` and isn't an attack (no crit, dodge or on-hit effects). Spell effects: `vfx.gd` and the status marks in `unit.gd` (visual only).

**Enemies:** GameManager asks its `OpponentProvider` for an `EnemyBoard` each fight and places it with `spawn_board()` (details: `docs/campaign-and-opponents.md`).
- Free play (`RandomOpponents`): count = player's unit cap, with a 30% chance of +1 or -1. Unit cost limited early (`max_cost = 1 + round/3`). Stats scaled by `enemy_base_scale + enemy_scale_per_round * (round-1)`. Random tiles, no stars, items or synergies (balance unchanged from before).
- Campaign (`WaveOpponents`): the level's authored wave for that round, times the level's `enemy_stat_mult`. Units can have stars, items and set tiles, and get synergies.
- Placement: only unlocked, empty enemy tiles (they unlock with the player's level). A set tile that's locked or taken falls back to the nearest open one; units that don't fit are skipped with a warning. Placed with `put_enemy_on_tile` (never the bench).

**Campaign:** `Campaign` -> `CampaignChapter` -> `CampaignLevel` in `tres/campaign/`. A level has one round per wave plus settings (start gold/level/HP for fresh starts, `start_heal`, income bonus, enemy strength, `loss_damage`, prep time, item drop rounds, allowed shop units) and `unlocks`. Waves (`EnemyBoard`) can have an `hp_reward`.
- **A chapter is one run (roguelite):** the first level starts fresh at 100 HP. Completing a level carries everything into the next level of the chapter: board and bench units (stars, items, tiles/slots), item bar, gold, player level, XP and HP. HP packs: the next level's `start_heal` on arrival plus `hp_reward` for beating certain waves; HP never exceeds the run's start HP.
- A level is complete when every wave is survived **and the last wave is won**; completion is saved. A lost final wave with HP left **comes again** next round (same round number, income again, no new item drop: `_replay_wave`, `start_prep(..., drops)`; "THE LAST WAVE COMES AGAIN"), so only running out of HP loses the level (it used to end the chapter run on one lost fight). **Defeat ends the chapter run**: Restart chapter goes back to its first level with an empty board. Finishing the last level completes the chapter; the next chapter starts fresh.
- The chapter run is saved (`SaveGame` `chapter_run`) when a level is completed (the next level's carry), and **while a level is played** (mid-level saves): at the start of every PREP, at the start of every fight, and when you leave during PREP (pause menu Main menu / Quit game, closing the window: `GameManager.save_mid_run`, called through the `game_manager` group by `GameState.go_to_menu` and the pause menu). The save is then this level's carry (as things are now) plus a `mid` block: round, phase, seed, both RNG states (as text: int64), streaks, drops, free rerolls, the 1-cost-shop flag, shop offers and lock, and the whole shared pool (format in `save_game.gd`). Continue resumes a `prep` save in that round's PREP (same shop, a full timer, no second income, drop or roll) and a `combat` save by replaying the fight from its start with the same board (fights are deterministic, so quitting can't dodge a loss). `GameState.begin_run` takes the save's seed and round and skips the start heal; `GameManager._restore_mid` puts back the rest after `_restore_carry`; `_resume_run` enters the phase. An unreadable `mid` (`SaveGame.mid_level`: version, round in range, phase, RNG keys) is dropped and the level starts from the carry. Only chapter levels write them (`saves_mid_level`): not the tutorial, free play or async PvP. Continue reads "Continue: <level>, wave 3/5 (72 HP)" partway through (`main_menu.continue_text`).
- **Start fight and fast forward:** chapter levels have no prep timer (the level's `prep_time` no longer times anything there): the top bar's START FIGHT starts the fight. Async PvP and chapter levels (`GameManager.can_fast_forward()`; not free play, the tutorial or lobbies) have a speed button beside it, 1x / 2x / 3x (`set_fight_speed`, remembered in `Settings.fight_speed`): `_physics_process` runs that many combat ticks per frame, so the fight is identical at any speed, and `Engine.time_scale` follows it during a fight only (animations, effects and fallers keep pace; back to 1 when the fight ends and when the scene goes). The bot presses Start fight itself.
- End screen: LEVEL COMPLETE with only Next level; CHAPTER COMPLETE with Next chapter (if any) / Play chapter again; DEFEAT with Restart chapter. Levels unlock in order (the first is always open). The round tracker shows "WAVE [pips] x/y" (hover for the level, wave name and enemies) and the standings name the wave.
- **Board biomes:** each level has a `theme` (BoardThemes, voxel tiles): tutorial forest; chapter 1 forest, jungle, snow; chapter 2 autumn, desert, volcano; chapter 3 cave, salt_flats, parasitic. Swamp, mushroom and mushroom_cave turn up in free play, async PvP and lobbies, which pick one of the 12 from the run seed. `GameManager._begin_run` applies it with the run seed, which lays out the world round the board (`CameraRig.widest_ground()` is the area to fill: the view zoomed all the way out, for a 2.4 aspect). To change a biome's look: edit `VoxelTiles.BIOMES` / `Props`, run `tools/make_voxel_tiles.tscn`, check with `tools/voxel_gallery.tscn`.
- `CampaignLevel.validate()` / `Campaign.validate()` report authoring mistakes and run at level start. The sample campaign has 3 chapters of 3 levels each (The Borderlands, The Ashen Frontier, The Shattered Sky; 63 waves in all, every chapter ending in a boss), tuned with `tools/bot_playtest -- chapter` so the difficulty steps down across chapters: with all 65 abilities in (retuned 2026-10-23) the bot completes about 65-75% of chapter 1 runs, 40% of chapter 2 and 33-45% of chapter 3 (12-run samples are noisy: the same settings gave 7/12 and 9/12 for chapter 1). `enemy_stat_mult` per level: ch1 1.07 / 1.26 / 1.16, ch2 1.02 / 1.11 / 0.875, ch3 0.63 / 0.53 / 0.82 (raised about 5% on 2026-10-25 after playtesters found it a bit easy; the new loss damage and longer backline ranges also changed it, not re-measured with the bot yet). Chapter 2's boss level has a cliff: 0.82 cleared 7/12, 0.85 cleared 2/12. A chapter always starts fresh (its first level sets its own gold and level); finishing it unlocks the next chapter's first level and the end screen offers Next chapter. Details and per-level settings: `docs/campaign-and-opponents.md`.

**Live lobbies (2-8 players):** built 2026-10-23; the full description, the decisions and how to plug in a hosted server are in `docs/multiplayer-design.md` ("Part 2: as built"). In short: the menu's Lobby screen plays offline against 1-7 bots, hosts a LAN game or joins one by address; a waiting room lets the host add bots and start. `LobbyServer` (`Scripts/lobby/`) is authoritative (seats, lobby-wide pool, timer, pairings, PvE rounds 1-3 then PvP, ghosts for an odd count, damage, placements, a disconnected player's seat stays idle (its board still fights; no bot plays it), rejoin by token) and knows nothing about networking; `LobbyNet` (autoload) carries `LobbyProtocol` JSON messages in-process or over ENet, and `--server [--port N]` on a headless build runs a dedicated server. In the game scene `GameManager.lobby` (`LobbyGame`) turns clicks into requests and shows what the server decided; fights are replayed from the server's fight description (`Arena.setup`) on the visible board, turned around for the away player. Mid-fight item drops are timed inputs (`Arena.INPUT_DELAY` ticks ahead) applied on every copy of the fight. Single player and the server share `PlayerRules` (every player action and the round economy) and `CombatRunner` (the fight loop, one per board). **Round 1 is the opening** for everyone (as in async PvP: a free 1-cost unit on the board, the shop shut, `opening_time` 4 s; `state.opening`). **The enemy half** shows the start tiles during prep (`Board.foe_level = 1` in `LobbyGame.begin`) and the opponent's own tiles in a fight. **Scouting:** click a player's row in the standings to see their board (`scout {seat}` -> `board {seat, level, units}`, asked again every 1.5 s while it is up; `LobbyGame.scout`, display copies under a `ScoutView` node, your own units hidden and nothing draggable); click your row or press Space (`scout_home` keybind) to come back; a fight starting brings you back. **The opponent's bench** shows on the far bench during a fight (`home_bench` / `away_bench` in the fight description, display copies under a `FoeBench` node). The Synergies tab counts only your side (`Unit.mine`), also from the away view. **Streaks** ride in `public` (win / loss) and show on the standings rows as animated marks (`StandingRow.StreakMark`: red flames for a win streak, blue droplets for a loss streak, from 2). Protocol version 4 (the state carries `recv` / `recv_items`: items the server handed out, for the client's pop-up). **Rules for code:** a new player action goes into `PlayerRules` (and an intent in `LobbyProtocol` + `LobbyServer._on_intent`); anything a fight depends on must be in the fight description, or the server's and clients' fights will differ; bump `LobbyProtocol.VERSION` when a message changes shape.

**Async PvP (ghost mode):** the menu's Async PvP starts a free-play run (shared pool, items) with `GameState.ghost_mode` set, so `GameManager` uses `SnapshotOpponents` instead of random enemies. **Trophies and lives, no HP:** a won fight is a trophy (+1 gold as usual), a lost one costs a life (`PlayerState.trophies` / `losses` / `lives_left()`, `Events.trophies_changed`); `GameState.ASYNC_TROPHIES` (10) wins the run, `ASYNC_LIVES` (10) losses end it, and there is no last round (`total_rounds()` = `ENDLESS_ROUNDS`). At 10 trophies the end screen says VICTORY and offers **Endless mode** (`GameManager.continue_endless`, `PlayerState.endless`; boss music): sudden death, the run goes on with one life (`losses` is set to 9; the standings show 1/1), trophies keep counting, until the first loss (ENDLESS OVER). The best trophy count is saved (`SaveGame.async_best`, shown in the menu tooltip). The top bar shows "TROPHIES [10 pips] 4/10" ("ENDLESS 14" after), the standings show lives out of 10 for you and for an async ghost (older or free-play ghosts show their HP). **Online ghosts:** with an address in `OnlineConfig` the boards go up to the ghost service and ghosts come from it (see Core scripts and `docs/online-ghosts.md`); ghost picks use `GameManager.ghost_rng`, not the run RNG, because online ghosts can arrive at any time. **Round 1 is the opening** (its fight gives no trophy and costs no life, since the free unit is luck; `_end_async_fight`) (`GameManager.is_opening`, `PlayerRules.start_prep(..., opening)` / `give_opening_unit`, `PlayerState.opening`): a random 1-cost unit from the pool is already on the board, the shop is shut (Buy XP and Reroll dim) and nothing can be bought, sold, moved, rerolled or levelled; the fight starts by itself after `OPENING_PREP` (4 s). **No prep timer after that** (`manual_start`, prep `UNTIMED`): the top bar shows a gold START FIGHT button in place of the clock (`top_bar_timer.gd`, `end_prep_early`), plus the fast-forward button (below). The enemy half opens as far as the ghost's own level (`Board.foe_level` from the ghost's `player_level`: the mirror of that player's open tiles; it read a missing `level` key until 2026-10-25, so it always followed yours), not yours; with no ghost it follows yours. At every fight start in free play and ghost mode, `_record_snapshot()` saves the player's board (units with stars and items, mirrored onto the enemy half by `BoardSnapshot.mirror`: `(x, y) -> (6-x, 7-y)`) with the round, level, HP, a balance hash and the run id to `LocalSnapshotStore`. When PREP starts the provider picks a ghost: same balance hash, same round (or one either side), level at most 1 above yours (nearest preferred), never from this run; if no ghost has today's balance hash (stats or synergies changed since it was recorded), an older ghost plays instead as long as every unit and item on it still exists (`SnapshotOpponents.still_playable`; it fights with today's stats and traits); the HP standings show it as this round's opponent ("Ghost of <name>" with its recorded HP), and the ghost spawns like any enemy board with synergies. With no match it falls back to random enemies. Ghost fights are deterministic (same boards, same result). Headless runs write to `user://snapshots_headless`, never your real `user://snapshots`. Campaign levels and the tutorial neither record nor use ghosts. Details: `docs/multiplayer-design.md` Part 1.

**Saves:** `SaveGame` (static, no autoload) keeps campaign progress (`completed_levels`: best HP, times, first completion), `unlocks`, the `chapter_run` in progress and the `team_plan` in `user://save.json` (version 2; version 1 files load fine). Writes go through a temp file; an unreadable save is copied to `.corrupt` and progress starts empty. Inside a chapter level the chapter run is saved every PREP and fight (mid-level saves, see Campaign above).

**Player HP:** Starts at 100. After every single-player fight a banner over the board says how it went (`Events.notice`, shown by `board_label.gd`): VICTORY +1 GOLD, or DEFEAT / TIME UP / BOTH SIDES FELL with the HP it cost (only wiping out the enemy wins). Loss damage = the stage's base damage + 1 per enemy unit still standing (stars don't matter; a clean wipe costs only the base): `GameState.STAGE_DAMAGE` stage 1: 0, 2: 2, 3: 6, 4: 7, 5: 10, 6: 12, 7: 17, 8 and later: 150 (`damage_for_loss(survivors)`, `stage_damage`; lobbies use the same in `LobbyServer._apply_result`). In a campaign level with `loss_damage` set, that replaces the stage's base (rounds restart every level, so the stage stays low). HP 0 = defeat screen; finishing the last round = victory screen (campaign: only if the last wave was won). The standings' HP number turns red at 25% of `start_hp` or less. Restart calls `GameState.reset()` then reloads the scene (campaign: from the chapter's first level).

**Items (v2, 2026-10-22; design: `docs/items-v2.md`, first version: `docs/items-plan.md`):** 15 `ItemData` types in `tres/items/` (all in Game Manager's `item_roster`).

Items still can't be taken off otherwise.
- **Resonance** (`resonance.gd`, class Resonance): two items with different elements on one unit switch on the pair's resonance (15 pairs: Juggernaut, Flurry, Vanguard, Hemorrhage, Spellblade, Second Wind, Bulwark, Undying, Lifebloom, Evasion, Frenzy, Tempest, Bloodward, Hex Ward, Soul Siphon), three different elements add Prism. Effects use the synergy effect keys and merge into each unit's effects in `Synergies.effects_for` (deterministic). Resonances used in a fight are saved as unlocks `resonance:<key>` (the book).
- **Drops:** free play drops **14 items** a run (`GameState.ITEM_DROP_ROUNDS`: 1-2, 1-3; 2-2, 2-4, 2-6; 3-2, 3-4, 3-6; 4-3, 4-6; 5-3, 5-6; 6-3, 6-6) plus Tinker's Tongs at the end of stages 2 to 6 (`TONGS_ROUNDS`: rounds 9, 15, 21, 27, 33; free play, async PvP and lobbies) and one in each chapter level, at its third wave (`CAMPAIGN_TONGS_ROUND`; none in the tutorial). The Tongs never count towards a unit's 3 items. `GameManager.pick_drop`: stages 1-2 basic only; from stage 3 a 30% chance (`SPECIAL_DROP_CHANCE`) of a special by `drop_weight` and `min_stage` (Ledger from 4, benders from 5 at a low weight, at most once a run each). Campaign levels keep their own drop rounds; their stage for the table is chapter-based (`drop_stage`: ch1 = 2, ch2 = 4, ch3 = 6, tutorial = 1). The inventory is unlimited and cleared by `reset()`.
- **Equipping:** drag an item from the Items tab onto one of your units (it goes to the unit whose body is nearest the pointer on screen, `DragController.unit_for_item`, so a neighbour standing in front doesn't catch it) (board or bench, any phase, also mid-fight); only the item's image follows the pointer (centred on it, no box). Fighting units get stat boosts at once; resonances and other effects start with the next fight.
- **On units:** each item is its icon image (`textures/ui/items/<id>.png`) in a row under the bars, over the head (`Unit.ICON_HEIGHT`): a static billboard sprite, 0.5 world units wide (`Unit.ICON_SIZE`; a row of three stays about one tile wide), drawn over the models; bound items show their stack count. Resonances show in the inspector and the Items tab, not on the board. (The voxel item models were tried and replaced on 2026-10-22.)
- **Stats:** flat item HP and damage (with stacks) add to base stats before the star and synergy multipliers; attack speed, damage reduction and omnivamp add to the synergy percentages; the 60% damage-reduction cap covers both. Enemies: free-play random enemies have no items; campaign waves and ghosts can carry any item (`BoardUnit.items` / `stacks`). Items are saved by `ItemData.id` (never rename an id). The 8 new items have placeholder icons (flat pixel art) until the art chat makes proper ones.

**Synergies (v2, 2026-10-22; full design: `docs/synergies-v2.md`):** 35 traits: 11 origins (Order, Celestial, Wild, Shadow, Arcane, Undead, Ember, Frost, Fey, Dwarven, Infernal), 16 classes (Warrior, Caster, Protector, Ranger, Rogue, Healer, Summoner, Monk, Bard, Alchemist, Brute, Warlock, Knight, Duelist, Elementalist, Trickster) and 8 uniques (Dragonlord, Ascendant, Lich King, Earthshaker, Rebirth, Soulreaper on 5-costs; Inferno, Crusade on 3-costs). Every unit has one origin and one or two classes (a unique replaces the second class), at most 3 traits.
- **Breakpoints, not curves:** only the highest tier reached applies, and each tier lists its whole effect. Shapes: vertical (Caster, Warrior 3/5/7/9; Wild, Dwarven 3/4/5/7), shallow (2/4/6, Protector 2/4/6/8), tight ladders (2/3/4/5, 2/3/4, 2/3), uniques (1). Deep top tiers have names (Archmagi, Warband, Stampede, Mountain's Heart, Bulwark, Deadeye, Cutthroat, Juggernaut, Soul Pact, Undying, Nightfall, Deep Freeze, Glamour, Heavenly Host).
- **Data:** `Synergies.DEFS[tag]` = kind, thresholds, desc, top, tiers; each tier has `self` (holders), `team` (every unit) and/or `tags` ({other tag: effects}, used by Lich King) effects plus the player-facing `text`. `Synergies.effects_for(units)` merges them per unit (most keys add; execute / revive / ramp take the max; crit / dodge take the smallest "every Nth"), `apply()` hands each unit its dict through `Unit.apply_synergy`, `preview()` is the same without changing units, `tier_text()` / `tooltip()` are the UI text.
- **Effect keys / mechanics** (all stepped by the fixed combat tick, nothing random): hp, dmg, as, dr (damage reduction, 60% cap with items), vamp (omnivamp; the `lifesteal` field), shield (of max HP at fight start, absorbed first, shown as a white overlay on the health bar), regen (of max HP per second), ramp + ramp_max (attack speed per attack), crit (every Nth attack x2), execute (kill a target left below % max HP; ignores reduction), revive (once per fight), burn (target's max HP per second for 3 s; orange health bar), chill (target attack speed down for 2 s, capped at 80%), dodge (every Nth attack against the unit misses, "MISS" popup), curse (target takes % more damage for 3 s), range (+tiles), kill_heal. **No trait uses mana** (user decision); mana feeds the unit abilities.
- `Unit._attack()` does an attack (dodge, crit, damage, omnivamp, burn / chill / curse, execute, kill heal); `Unit.take_damage(amount, by, attack, pierce)` applies curse and reduction, the shield, mana from hits and revive; `_tick_effects()` runs regen, burns and the timers each tick.
- Each unique unit on the board counts once per tag. `Synergies.apply()` runs at combat start (both teams; campaign and ghost enemies get synergies, free-play random enemies don't); `Unit.end_combat()` clears it.

## Conventions and gotchas

- **Tooltip style:** the project theme `tres/ui_theme.tres` (`gui/theme/custom` in project.godot) styles only TooltipPanel (HUD plate fill, lit top edge, dark bottom lip, soft shadow) and TooltipLabel (Atkinson Hyperlegible Bold 13 px, ink), so every tooltip in the menu and the run matches the HUD. `Tip.width_of` measures with that font and size.
- **Tooltips must be wrapped.** Godot does not wrap tooltip text, so a long single line runs off the screen (the Async PvP tooltip was 1783 px wide in a 1152 px window). Always write `tooltip_text = Tip.wrap("...")` (or `return Tip.wrap(...)` from `_get_tooltip`); `Tip.wrap` breaks lines at 340 px using the real font, keeping your own newlines. Keep tooltips short anyway. `tools/tooltip_checks` builds every screen and measures every tooltip (the free-play HUD, planner, items, all synergy tags, menu panels, campaign stage label, tutorial); run it after adding any tooltip.
- One function per name per script: Godot errors on duplicates, and many past bugs were leftover copies of replaced functions.
- When looping over untyped arrays or dictionaries, type variables explicitly (`var c: Vector2i = key`) to avoid "cannot infer type" errors.
- Exported scene references (`@export var tile_scene`) reset when a script is re-attached; prefer `preload`.
- Units must be instances of `unit.tscn` under `Board/Units`; `unit.gd` finds the board via `get_parent().get_parent()` and needs `ModelHolder`.
- Never place enemies with `put_on_tile` (it falls back to the bench); use `put_enemy_on_tile`.
- Combat is deterministic; keep it that way: no tweens or frame delta in combat logic, no unseeded random (see Combat rules). Run `tools/combat_checks` after touching combat.
- `game_manager.gd` joins group `game_manager`; other scripts find it with `get_first_node_in_group` (its node name "Game Manager" has a space, so path lookups are fragile).
- `GameManager.unit_pool` is the roster export (all unit types). The limited-copies pool is `GameManager.shared_pool` (UnitPool). Don't confuse them, and don't rename the export (main.tscn stores its value by name).
- Testing without the editor: `Godot_v4.7.2-stable_win64.exe --headless --path . --quit-after 600` runs the main scene for ~10 s and prints script errors. Autoloads don't exist in `--script` mode, so test scripts that touch GameState/Events must run through the main scene. After adding a new `class_name` script, headless runs don't know the class until Godot rescans: open the editor, or run `--headless --path . --import` once.
